🛠️ Deep Code Architecture Breakdown1. Global Topology & State Definitions (CONFIG)The configuration block establishes the operational parameters:DOMAIN_FILTERS: The exact DNS zones (like your Headscale control plane domain) targeted for active migration.PRIMARY_HEALTH_URLS: An array of critical HTTP endpoints. Because it’s configured as an array, you can pass multiple internal health checks (e.g., checking if Headscale, Dex, and MinIO are all simultaneously up).TIMEOUT_MS (5000): Sets a strict 5-second deadline. If your primary server stalls or drops packets for more than 5 seconds, it is marked as dead.2. Strict Consensus Health Probing (checkUrl & isPrimaryHealthy)The monitoring logic leans on a zero-tolerance failure policy:JavaScriptfor (const url of urlsArray) {
  const serviceAlive = await checkUrl(url);
  if (!serviceAlive) {
    return false; // Instant fail if any single service is down
  }
}
Asynchronous Isolation: checkUrl leverages a JavaScript AbortController signal to forcefully terminate hangs, treating slow/stuck connections as an outright outage.Strict AND Gate: The isPrimaryHealthy function iterates through every provided URL. If even a single service fails to return a HTTP 2xx OK status, the script instantly breaks the loop and triggers a full network failover. This guarantees that if a database crashes but the underlying server is still technically "pingable", the system correctly drops over to the secondary node.3. Edge-Driven Cloudflare DNS Manipulation (getAllDNSRecords & updateDNSRecord)Instead of proxying actual network packets (which introduces high latency), this script uses the Cloudflare v4 API to manipulate the global DNS routing table programmatically.Filtering Logic: It fetches up to 100 type-A records inside your zone and applies a substring match against your filter array. This limits modification commands strictly to your core application subdomains.PATCH Execution: When updating an IP address, it performs a PATCH request rather than a full PUT. This edits only the IP destination target (content) while completely preserving your preconfigured settings like TTL or your Cloudflare proxy (orange cloud) status.4. Convergence State Machine (runFailover)The core routing matrix acts as a simple, stateless deterministic looping mechanism over your filtered records:System StateCurrent Record ContentExecuted ActionResulting BehaviorPrimary HealthyPoints to Secondary IPPATCH to Primary IPAutomated Failback: The primary server has recovered; traffic is cleanly routed home.Primary HealthyPoints to Primary IPNo ActionSteady State: Core traffic routes to the primary node.Primary OutagePoints to Primary IPPATCH to Secondary IPFailover Event: Diverts users to the backup node automatically.Primary OutagePoints to Secondary IPNo ActionDegraded State: The system is maintaining operations entirely on the secondary host.5. Runtime Execution TriggersThe script exports two standard Cloudflare runtime hooks:scheduled(event, env, ctx): Binds directly to Cloudflare’s background Cron Triggers. This typically executes every 60 seconds, completely automating the health checking without human intervention.fetch(request, env, ctx): Exposes a web endpoint. This lets you manually trigger a routing health check or simulate an instant failover by pinging the Worker URL directly from a terminal or monitoring dashboard.📋 Portfolio Engineering Highlights💡 Why This Design is Elegant:Serverless High Availability: The monitoring bot doesn’t run on your primary or secondary infrastructure. If your entire data center goes dark, this script still runs flawlessly because it lives distributed inside Cloudflare’s global edge network.Zero-Inertia Rebalancing: Traditional DNS caching can take hours to update due to downstream TTL parameters. Because this updates the entry directly on Cloudflare’s authorative nameservers, traffic redirection to your standby machine happens almost instantaneously worldwide.
